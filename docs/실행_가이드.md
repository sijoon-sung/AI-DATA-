# 실행 가이드: 정책 카탈로그(이름이 아니라 내용으로 지역 정책 묶기)

다른 PC에서 처음부터 돌리고 결과를 돌려주는 방법이다. 명령은 모두 저장소 루트(`AI-DATA-` 폴더)에서 실행한다.

## 0. 준비 (처음 한 번)

1. 코드를 받는다.

   ```
   git clone https://github.com/sijoon-sung/AI-DATA-.git
   cd AI-DATA-
   git checkout cleanup-stage0
   ```

   이미 받았다면 `git pull`만 한다.

2. 실행 환경을 만든다.

   ```
   conda env create -f environment.yml
   conda activate council-diffusion
   ```

   - 이미 쓰는 환경이 있으면 `pip install bm25s==0.2.14`만 더 한다.
   - NVIDIA GPU가 필요하다. LLM 단계는 VRAM 8GB 이상에서 돌렸다.

3. 대회 데이터 zip 두 개를 `data/raw/`에 그대로 둔다(압축을 풀지 않는다).

   ```
   data/raw/2024_광역 회의록.zip
   data/raw/2025_광역 회의록.zip
   ```

4. 전처리를 한다(약 15분, CPU). `data/processed/`가 이미 있으면 건너뛴다.

   ```
   python scripts/02_preprocess.py
   python scripts/02b_dedupe.py
   python scripts/04_passages.py
   ```

## 1. 환경 점검

```
python scripts/15_policy_topics.py check
```

| 표시 | 뜻 |
|---|---|
| `OK` | 준비됨 |
| `!` | 경고(예: 색인이 일부만 있음). 다음 단계에서 만들어진다 |
| `X` | 고쳐야 함. 아래 "문제 해결"을 본다 |

LLM 줄이 `OK  로컬 LLM(Qwen2.5-7B) 응답: 2`로 나와야 LLM 단계가 돈다. 처음 실행하면 모델(약 4.7GB)을 내려받는다.

## 2. 한 번에 돌리기

```
python scripts/run_catalog.py
```

다음 순서로 자동 진행한다. 실패하면 그 단계에서 멈춘다. 같은 명령을 다시 실행하면 이어서 한다(색인은 끝난 의회를, LLM 단계는 끝난 주제를 건너뛴다).

| 단계 | 하는 일 | 시간(RTX 4060 기준) |
|---|---|---|
| check | 환경 점검. LLM이 안 되면 여기서 멈춘다 | 1분 |
| 색인(09) | 의회별 BM25 + bge-m3 벡터 | 약 2.5시간 |
| fit | 문단 표본을 의미로 묶어 주제 중심 800개 | 수 분 |
| assign | 모든 문단을 가장 가까운 주제에 배정 | 수 분 |
| describe | 주제별 대표 문단 | 1분 |
| label | 로컬 LLM이 주제마다 정책 여부, 이름, 정의, 의회별 정책 이름을 붙인다 | 주제당 약 8초(800개면 약 2시간) |
| family | 정의가 가까운 정책 주제 합치기 | 수 분 |
| names | 의회별 정책 이름마다 그 이름이 나온 문장으로 벡터를 만들어 이름끼리 묶기 | 10~20분 |
| eval | 평가 전용 정답(`eval/gold_families.json`)과 비교 | 1분 |

**옵션**

```
python scripts/run_catalog.py --skip-label          # LLM 단계(label·family·names) 없이 빠르게 확인
python scripts/run_catalog.py --until 2024-12-31    # 갱신 실험: 2024로 만들고 2025를 나중에 배정
python scripts/run_catalog.py --k 200               # 주제 수 바꾸기
```

**주의**
- 다른 무거운 GPU·CPU 작업과 함께 돌리면 크게 느려진다(10/11에 다른 실험과 겹쳐 색인이 12배 느려졌다).
- 노트북은 절전으로 멈추지 않게 전원 설정을 바꿔 둔다.

## 3. 결과 돌려주기

결과는 `data/catalog/topics/`에 생긴다.

| 파일 | 내용 |
|---|---|
| `eval.json` | 평가 결과(쌍 정밀도·재현율, 이름별 배정) |
| `labels.jsonl` | 주제별 LLM 이름(회의록 고유명사 포함) |
| `names.parquet` | 의회별 정책 이름과 이름 가족 |
| `topics.parquet` | 주제별 크기, 의회 분포, 대표 문단 ID |
| `families.parquet` | 정책 가족 |
| `fit.json` | 설정 |
| `centroids.npy`, `assign_*.parquet` | 주제 중심, 문단 배정(크다) |

**공개 GitHub 저장소에 올리지 않는다.** 대회 데이터에서 만든 결과라 규정상 제3자에게 공개하면 안 된다. 이 폴더는 `.gitignore`로 막혀 있으니 `git add -f`로 강제로 넣지 않는다.

대신 다음 중 하나로 전달한다.
- 같은 PC이면 그대로 두면 된다.
- 다른 PC이면 다음 명령으로 압축한 파일을 비공개로 옮긴다(USB, 개인 클라우드 등). 받는 쪽은 같은 위치에 푼다.

  ```
  python -c "import shutil; shutil.make_archive('catalog_results', 'zip', 'data/catalog/topics')"
  ```

  큰 파일(`assign_*.parquet`, `centroids.npy`)을 빼도 분석은 할 수 있다. 다만 다시 실행하려면 필요하다.

## 4. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `check`에서 LLM이 `X` | `llama-cpp-python`이 없거나 CUDA DLL을 못 찾는다. `pip install llama-cpp-python==0.3.36 --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cu124`. Windows에서는 코드가 torch의 `lib` 폴더를 PATH 앞에 붙여 DLL을 찾게 한다(`src/qa.py`의 `load_llm`) |
| 모델 내려받기 실패 | 인터넷 연결 확인. Hugging Face의 `Qwen/Qwen2.5-7B-Instruct-GGUF` 저장소의 q4_k_m 파일 두 개를 받는다 |
| `CUDA out of memory` | 다른 GPU 프로그램을 끈다. 색인 단계는 `python scripts/09_build_index.py --part dense --batch 64`로 배치를 줄인다 |
| 색인이 매우 느림 | 다른 무거운 작업(학습, 다른 실험)을 끄고 돌린다 |
| `label`이 중간에 멈춤 | 다시 실행하면 끝난 주제는 건너뛴다(`labels.jsonl`에 한 줄씩 저장됨) |
| `eval`에서 이름이 0건 | 그 브랜드의 의회 색인이 아직 없다. 색인을 마저 만든다 |

## 5. 결과 읽는 법

- **쌍 정밀도:** 시스템이 같은 가족으로 묶은 이름 쌍 중 정답도 같은 가족인 비율. 낮으면 다른 정책이 섞였다는 뜻이다.
- **쌍 재현율:** 정답에서 같은 가족인 이름 쌍 중 시스템도 같이 묶은 비율. 낮으면 같은 정책이 갈라졌다는 뜻이다.
- **섞여 들어온 음성 대조:** 하이패스·투어패스·문화예술패스처럼 이름만 비슷한 다른 정책이 교통비 가족에 들어갔는지. 비어 있어야 한다.
- **정답 파일은 평가 전용이다.** `eval/gold_families.json`은 시스템이 읽지 않는다. 시스템은 회의록만 보고 이름과 가족을 찾는다.
