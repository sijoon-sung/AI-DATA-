# 아키텍처

작성일: 2026-10-06. 사용 모델의 라이선스 확인 결과는 `00_대회_규정.md` 8절에 있다.

## 설계 원칙

- 의미를 판단해야 하는 지점은 학습한 딥러닝 모델이 맡는다. 판단 지점은 다섯 가지다.
  1. 어떤 발언이 정책 논의인가
  2. 어떤 이슈를 말하는가
  3. 다른 지역을 참조한 것인가
  4. 앞으로 어디로 번질 것인가
  5. 근거가 주장을 뒷받침하는가
- 정답이 하나로 정해지는 처리는 규칙으로 둔다. HTML 파싱, 지역명 사전 매칭, 인용 문자열 대조가 여기에 해당한다.
- 모든 판정 결과는 (doc_id, start, end)를 갖는다. 그래서 회의록명, 회의일자, 원문 구간을 언제든 꺼낼 수 있다.
- 최종 판단은 작은 미세조정 모델(1억~5억 파라미터)이 내린다. LLM은 근거를 문장으로 옮기는 일만 맡는다.

## 전체 구조

```
[L0 수집·정규화]  완료
 HTML → 평문 → 중복 제거 → 발언·안건 분리 (문자 위치 보존)
        │
[L1 분석 단위 생성]
 발언을 400자 안팎의 문단(passage)으로 나눔, 원문 위치 유지
        │
[L2 문단 판정 모델]  딥러닝: 다중 과제 인코더 1개
 ├ (a) 정책 논의 / 의사진행 구분
 ├ (b) 정책 용어 구간 태깅
 ├ (c) 타 지역 언급의 성격 분류 (정책 참조 / 단순 비교 / 협력 / 무관)
 └ (d) 하향 요인 분류 (상위법 개정, 정부 지침 등에 따른 논의인지)
        │
[L3 이슈 계층]  딥러닝: 임베딩 + 재순위 모델
 정책 용어 → 임베딩 군집 → 표준 이슈 목록
 이슈별 언급 탐색 (바이 인코더로 후보 검색 → 크로스 인코더로 확정)
        │
[L4 이벤트 계층]  집계와 규칙
 이슈 × 의회 × 월 언급 강도 (회의량으로 정규화)
 의회별 최초 관측, 급증 시점, 참조 연결 (근거 수준 포함)
        │
[L5 확산 모델]  딥러닝
 ├ 이슈 유형 분류기: 공통 외부요인형 / 순차 확산형 / 단일 지역형
 └ 확산 예측기: 그래프 주의집중 기반 위험률 모형 → 의회별 다음 기간 등장 확률
        │
[L6 서술·검증]  딥러닝: 로컬 LLM + 검증 모델
 근거 묶음(JSON) → 오픈 LLM이 서술 → 인용 문자열 대조 + 함의 판정 모델로 검증
        │
[L7 서비스]
 이슈 검색 → 의회별 타임라인 → 의회 간 흐름 지도 → 근거 원문 보기
```

용어 풀이
- 바이 인코더: 문장을 각각 벡터로 바꿔 빠르게 검색하는 방식이다.
- 크로스 인코더: 두 문장을 함께 읽고 정밀하게 판정하는 방식이다. 느리지만 정확해서, 후보를 걸러 낸 뒤에만 쓴다.
- 약지도 학습: 규칙이나 데이터 구조에서 자동으로 만든 불완전한 라벨로 먼저 학습하는 방법이다.
- 함의 판정(NLI): 한 문장이 다른 문장을 논리적으로 뒷받침하는지 판정하는 과제다.

## 모듈별 설계

| 모듈 | 판단 내용 | 모델 (오픈, 로컬 실행) | 학습 데이터 출처 | 평가 지표 |
|---|---|---|---|---|
| L2 문단 판정 | (a)~(d) | `monologg/koelectra-base-v3-discriminator`에 출력층 4개를 붙인 다중 과제 모델 | 약지도 라벨 + 사람이 검수한 정답셋 | 과제별 F1 |
| L3 이슈 정규화 | 표기가 다른 용어를 같은 이슈로 묶기 | `BAAI/bge-m3` 임베딩 + 군집 (대안 `nlpai-lab/KURE-v1`) | 의회 간 같은 제목의 조례안 쌍을 양성 예시로 대조 학습 | 군집 순도 (표본 검수) |
| L3 언급 연결 | 이 문단이 이 이슈를 논의하는가 | `bge-m3` 후보 검색 → `BAAI/bge-reranker-v2-m3` 미세조정 | 이슈별 양성·음성 문단 정답셋 | 정밀도, 재현율 |
| L5 유형 분류 | 이슈의 확산 유형 | 의회 × 시간 행렬을 입력받는 소형 시계열 모델(GRU) | 규칙으로 만든 약지도 라벨 + 사람 검수 | macro-F1 |
| L5 확산 예측 | 의회 i가 다음 기간에 이슈 k를 다룰 확률 | 그래프 주의집중망(GAT) + 이산시간 위험률 손실 | 데이터 자체 (실제 등장 여부) | AUC, Brier 점수, 상위 k 적중률 |
| L6 서술 | 결과표 문장 작성 | `Qwen/Qwen2.5-7B-Instruct` 4비트 양자화 | 학습하지 않음 (근거 묶음만 입력) | 인용 일치율 |
| L6 검증 | 인용 구간이 주장을 뒷받침하는가 | KoELECTRA를 한국어 NLI 데이터(KLUE-NLI, KorNLI)로 미세조정 | 공개 NLI 데이터 + 소량 정답셋 | 정확도 |

### 확산 예측기 (L5)의 내부 구조

```
노드 = 17개 의회, 시점 = 월
노드 입력: 해당 이슈의 언급 강도 이력, 의회 안건과 이슈의 임베딩 유사도, 하향 요인 신호
엣지 입력: 지리 인접, 권역, 타 지역 참조 횟수(L2-c 결과), 과거 선후 관측 빈도
   │
GRU(시간 축) → 그래프 주의집중(의회 간) → 위험률 h(i, t+1)
   │
손실: 아직 이슈가 등장하지 않은 의회만을 대상으로 한 이진 교차엔트로피 (이산시간 생존분석과 같은 형태)
```

- 이슈 하나로는 노드가 17개뿐이라 학습할 수 없다. 그래서 수백 개 이슈의 확산을 모아서 하나의 모델을 학습한다.
- 주의집중 가중치는 어느 의회의 선행 논의가 예측에 크게 작용했는지 보여 준다. 다만 이를 인과로 서술하지 않고 "예측에 기여한 선행 관측"으로만 표현한다.
- 통계 기준선(로지스틱 사건사분석)을 함께 돌려, 딥러닝 모형이 기준선보다 나은지 수치로 보인다.

## 라벨이 적은 문제를 푸는 방법

| 라벨 출처 | 쓰임 |
|---|---|
| 같은 회의록의 안건 제목 (그 회의에서 논의된 정책 용어) | L2-(b) 용어 태깅의 원격 지도 라벨 |
| 발언자 직함과 정형 문구 ("의석을 정돈하여", "의사봉 3타" 등) | L2-(a) 의사진행 문단 라벨 |
| 지역명과 정책어의 공기 규칙 ("○○도는 이미 조례를" 등) | L2-(c)의 1차 후보 |
| "법 개정에 따라", "정부 지침" 같은 문구 | L2-(d)의 1차 후보 |
| 의회 간 같은 제목의 조례안 | L3 임베딩 대조 학습의 양성 쌍 |
| 실제 등장 여부 | L5 예측기의 정답 (별도 라벨 불필요) |

- 1차 라벨은 규칙으로 자동 생성한다.
- 판단이 애매한 표본은 사람이 검수해 정답셋으로 확정한다. 과제당 300~500건이 목표다.
- KISTI 인프라를 받으면 더 큰 오픈 모델로 사전 라벨을 달고 사람이 검수하는 방식도 쓴다.
- 같은 정답셋으로 다음 세 가지를 비교해, 작은 미세조정 모델로 충분하다는 근거를 수치로 보인다.
  1. 규칙만 쓴 방법
  2. 작은 미세조정 모델
  3. 대형 모델의 제로샷 판정

## 대회 제약과의 대응

| 제약 | 대응 |
|---|---|
| 상용 API 금지 | 모든 모델을 로컬에서 실행한다 |
| 기간 밖 정보 금지 | 2024 학습 → 2025 검증에서 미래 정보가 섞이지 않도록, 서술용 LLM은 2025년 이전에 공개된 모델을 쓴다. LLM은 예측에 쓰지 않는다 |
| 인과 단정 금지 | 연결마다 근거 수준을 붙이고, 주의집중 가중치는 "기여"로만 표현한다 |
| 재현성 | 판정 결과 캐시와 처음부터 다시 실행하는 경로를 함께 낸다. 분류기 추론은 CPU로도 돌아간다 |
| 저작권 | 라이선스가 명시된 모델만 쓴다 |

## 계산량 추정 (아직 재지 않은 추정치)

- 본문 4.16억 자를 400자 문단으로 나누면 약 100만~150만 개다. 의사진행 문단과 짧은 발언을 거르면 더 줄어든다.
- RTX 4060 Laptop(8GB)에서 base 크기 인코더를 fp16으로 추론하면 초당 수백 건이므로, 전체 판정에 1~2시간이 걸릴 것으로 본다.
- 미세조정은 정답셋 규모가 작아서 과제당 수십 분 안에 끝날 것으로 본다.
- 7B LLM은 결과표에 들어갈 이슈 수십~백여 개의 서술에만 쓴다.
