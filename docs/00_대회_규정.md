작성일: 2026-10-06. 각 항목 끝의 괄호는 출처이며, 출처 목록은 문서 끝에 있다.
규정 원문을 옮긴 부분과 우리가 해석한 부분은 "해석:"으로 구분한다.

## 1. 대회 개요와 일정

- 대회명은 「2026 DATA·AI 분석 경진대회」이고, 주관은 KISTI다. 이 문제는 문제해결 부문의 정책지정 문제이며, 출제 기관은 국회도서관이다. [S1]
- 문제명은 「광역 지방의회 회의록 기반 지방정책 이슈 트랜드 분석 및 흐름 예측」이다. [S1]
- 참가 신청과 결과 제출 기간은 2026-09-15부터 2026-11-06까지다. 서류평가는 11/9~11/13, 발표평가와 시상은 11/25(KISTI 대전 본원)에 있다. [S1, S4]
- 참가 절차는 다음과 같다. [S6]
  1. aida.kisti.re.kr에 로그인한다(KAFE 연동 로그인 가능).
  2. 문제 페이지에서 "참여하기"를 누르고 팀 정보, 프로젝트 제목, 간략 소개, 데이터 처리 인프라 필요 여부를 입력해 신청한다.
  3. 마이페이지의 참가신청 탭에서 상태가 "통과"로 바뀌면 승인된 것이다.
  4. 승인 후 문제 페이지에 생기는 결과제출 탭에서 zip 파일을 올린다. 문서자료는 필수이고 모델자료는 선택이다.
- 문의는 문제 페이지의 QnA 탭이나 운영사무국 메일(aidatacon@gmail.com)로 한다. [S4]

## 2. 분석 범위에 관한 규정

- **'최초 등장'**은 제공 데이터 범위 안에서 처음 관측된 시점을 뜻한다. [S1]
- **'전파·확산 흐름'**은 회의록에 나타난 시간적 선후관계와 명시적인 상호 참조를 바탕으로 추정해야 한다. 근거 없이 지방의회 사이의 인과관계를 단정해서는 안 된다. [S1]
- 결과물은 주요 이슈 키워드, 데이터 범위 내 최초 관측 시점, 다른 지방의회에서의 후속 논의 흐름, 향후 확산 가능성을 항목별 서술형으로 제시해야 한다. 각 분석 결과에는 판단 근거가 된 회의록명, 회의일자, 원문 구간을 함께 제시해야 한다. [S1]
- 향후 예측에는 주최 측이 정한 분석 기준일까지의 정보만 사용해야 한다. [S1]
- 분석과 예측에는 제공 데이터의 수록 기간을 벗어난 정보를 활용할 수 없다. 제공 데이터 이후 시점의 외부 정보를 추가해 분석하거나 예측해서는 안 된다. [S3]
- 해석: 수록 기간은 2024-01-01부터 2025-12-31까지다. 2024년 이전 정보를 문제 배경 설명에만 인용하는 것과, 기간 안 외부자료를 보조로 쓰는 것이 허용되는지는 아직 확인되지 않았다(7절 참조).

## 3. 모델과 도구 사용에 관한 규정

- **사전학습 모델, 외부 API, 외부 자료를 사용할 수 있다.** 다만 명칭, 버전, 용도, 적용 범위를 기술문서에 명시해야 한다. [S1]
- **제공 데이터를 외부로 전송하는 상용 LLM API(OpenAI, Anthropic 등)는 사용할 수 없다.** 제공 데이터가 외부로 전송되지 않는 자체 실행형 오픈 모델은 사용할 수 있다. [S3]
- 대회 참가자가 활용하는 데이터와 도구는 저작권 문제가 해결된 것만 사용할 수 있다. [S4, S5]
- 제공 데이터 외에 활용한 데이터, 코드, 모델, 라이브러리가 있으면 저작권과 이용조건에 문제가 없는지 확인해야 한다. [S2]
- 외부 AI 서비스나 API가 실행에 필요하면 서비스명, 사용 모델, 주요 설정을 README.md에 적고, 심사용 임시 인증정보를 따로 제공해야 한다. [S2, S3]
- 해석: Hugging Face 등에서 받은 오픈 인코더, 임베딩 모델, LLM을 로컬에서 실행하고 미세조정하는 것은 허용된다. 다만 라이선스가 명시되어 있고 재배포가 가능한 모델을 골라야 한다. 수상작은 공개되기 때문이다(6절).

## 4. 제공 데이터 이용에 관한 규정

- 제공 데이터의 출처는 각 광역 지방의회이며, 경진대회 외의 목적으로 사용할 수 없다. [S1]
- 참가신청서 서약 내용은 다음과 같다. [S5]
  - 승인받은 목적 외의 용도나 불법적인 용도로 이용하지 않는다.
  - 승인받은 이용자가 아닌 제3자에게 열람, 제공, 대여, 판매하지 않으며, 보안과 관리를 철저히 한다.
  - 개인정보가 포함된 경우 개인을 식별할 수 있는 형태로 바꾸지 않는다. 재식별 가능성이 있으면 이용을 중지하고 주최 측에 알린 뒤 폐기한다.
  - 대회가 끝나면 제공 데이터를 폐기한다.
  - 논문이나 출판물로 성과를 낼 때 데이터 출처를 명시한다.
- 결과물에 개인정보, API 키, 비밀번호 등 공개하면 안 되는 정보가 들어가지 않게 확인해야 한다. [S2]
- 해석: 원자료와 가공 데이터는 공개 저장소에 올리지 않는다. 이를 위해 프로젝트 폴더에 `.gitignore`를 두었다. 회의록 속 의원과 공무원의 직함, 이름은 공적 기록이지만, 민원인 등 일반인 정보가 인용 구간에 들어가지 않는지 결과표를 만들 때 점검한다.

## 5. 제출물에 관한 규정

**폴더 구성** [S2]
- `README.md`: 결과물 구성, 데이터와 모델, 학습·평가(추론) 방법, 실행환경을 설명한다.
- `data/`: 학습과 평가에 쓴 데이터
- `model/`: 학습된 모델 파일
- `src/`: 데이터 처리, 모델 구조, 학습과 평가 소스코드
- `notebooks/`: 실행 가능한 Jupyter Notebook
- `scripts/`: 환경 설정, 데이터 처리, 학습과 평가 스크립트
- `demo/`: 테스트나 추론 과정을 보여 주는 데모영상
- `figures/`: 설명용 그림
- 쓰지 않는 폴더는 생략할 수 있으며, 그 경우 README.md에 구성을 설명한다.

**실행환경** [S2]
- README.md에 운영체제, Python 등 주요 프로그램 버전, 주요 라이브러리와 버전, GPU를 쓰는 경우 NVIDIA 드라이버와 CUDA 버전, 환경 구성과 실행 방법을 적는다.
- 환경 재현 파일을 함께 낸다. uv를 쓰는 경우 `pyproject.toml`과 `uv.lock`을 제출한다.
- 문제 페이지는 전체 소스 코드, 전처리 코드, 실행 방법 문서, 실행환경과 라이브러리 버전, 예시 입력과 출력의 제출을 요구한다. [S1]

**노트북** [S2]
- 데이터 불러오기와 전처리, 모델 구성과 학습, 평가와 추론, 주요 결과 확인과 시각화를 실행 순서대로 구성한다.

**기타** [S2]
- 주요 기능과 처리 과정에 주석을 단다.
- 데모영상을 반드시 포함한다.
- 심사 과정에서 재현성 검증을 위해 제출 코드를 실제로 실행할 수 있다. [S3]

**AI 활용범위와 주요 검토 과정** [S2]
생성형 AI나 AI 기반 도구를 썼다면 아래 여섯 항목을 간략히 적는다. 쓰지 않았다면 "미사용"으로 적는다.
1. 활용 도구 (가능하면 모델명과 버전 포함)
2. 활용 단계: 문제 분석, 아이디어 탐색, 데이터 처리, 모델 설계, 코드 작성, 실험, 결과 분석, 문서 작성 등
3. 주요 활용 내용
4. 참가자 주요 기여와 검증: 직접 판단, 선택, 수정, 검증한 사항
5. 검토한 대안과 실패 사례
6. 최종 선택 이유

이 항목은 AI 활용 비중을 평가하려는 것이 아니라, 참가자의 판단, 선택, 검증 과정을 확인하려는 것이다. 모든 프롬프트나 대화를 낼 필요는 없다.

**제출 전 확인 목록** [S2]
- [ ] README.md에 구성과 실행 방법이 설명되어 있는가
- [ ] 실행환경과 라이브러리 버전이 명시되어 있는가
- [ ] 학습과 평가(추론) 과정을 확인할 수 있는가
- [ ] 데모영상이 포함되어 있는가
- [ ] 외부 데이터, 코드, 모델의 이용조건을 확인했는가
- [ ] 개인정보와 인증정보가 포함되어 있지 않은가
- [ ] AI 활용범위와 주요 검토 과정을 작성했는가

## 6. 평가와 시상

- **배점**은 창의성 20점, 우수성 50점, 효과성 30점이다. [S4]
  - 창의성: 독창적인 아이디어인가, 새롭고 가시적인 차별성이 있는가
  - 우수성: 내용이 충실하고 대회 목적과 연관성이 충분한가, 구체적이고 완성도가 높은가
  - 효과성: 관심을 끌 만큼 흥미롭고 홍보효과가 있는가, 활용성이 높은가
- 문제별 평가 기준은 두 가지다. [S1]
  - 핵심 이슈 도출, 이슈의 최초 등장 시점, 다른 지방의회로의 전파 경로를 얼마나 정밀하게 추적했는가
  - 핵심 이슈의 파급 흐름 예측이 논리적으로 타당한가
- 문제해결 부문 상금은 대상 300만 원(국회의장상), 최우수상 200만 원(과학기술부총리상), 우수상 5팀 각 100만 원(국회도서관장상 등)이다. 우수 수상자에게는 학술대회 발표 기회가 주어진다. [S4]
- 여러 문제에 중복 참여할 수 있지만 중복 수상은 할 수 없다. 적합한 결과가 없으면 시상하지 않을 수 있다. 심사점수는 공개하지 않으며 이의를 제기할 수 없다. [S4]
- 수상자는 최종 제출물, 코드, 문서를 주최 측에 전달하고 DataON과 AIDA 홈페이지를 통한 공개에 동의한다. [S5]
- 다른 유사 행사에서 수상했거나 타인의 지적재산권을 침해한 경우 수상을 취소하고 상금을 회수한다. [S4, S5]
- 문제를 제출한 개인이나 기관에 소속된 직원은 해당 문제에 참여할 수 없다. [S4]

3. 수록 기간 안에 공개된 외부자료(국회 의안정보, 자치법규 공포일 등)를 보조로 써도 되는지
4. 분석 기준일이 2025-12-31인지

| 분류기 대안 | `klue/roberta-base` | 모델 카드에 표기 없음 (KLUE 저장소는 CC BY-SA 4.0) | 보류. 라이선스가 명확하지 않음 |
| 소형 LLM 대안 | `Qwen/Qwen2.5-3B-Instruct` | 기타 (Qwen Research 라이선스) | 제외 |

- 모든 모델은 로컬에서 실행하며, 제공 데이터를 외부로 보내지 않는다.
- 2024년 학습 → 2025년 검증 실험에서 미래 정보가 섞이지 않도록, 서술용 LLM은 2025년 이전에 공개된 모델을 쓴다. LLM은 예측에 쓰지 않는다.
- 최종 제출 전에 각 모델의 라이선스 원문을 다시 확인하고 README.md에 명칭, 버전(커밋 해시), 용도, 적용 범위를 적는다.

## 9. 규정을 우리 작업에 적용한 결과

| 규정 | 우리 작업에서의 조치 |
|---|---|
| 인과 단정 금지 | 의회 사이의 연결마다 근거 수준(명시적 참조 / 시간 선후)을 표시하고, 시간 선후만 있으면 "선행 관측", "후행 관측"으로만 쓴다 |
| 근거 제시 | 모든 판정 결과가 (doc_id, start, end)를 가지므로 회의록명, 일자, 원문 구간이 자동으로 붙는다 |
| 기간 외 정보 금지 | 분석과 예측은 2024~2025년 회의록만으로 한다. 2026년 사건(전남광주 통합 등)은 쓰지 않는다 |
| 상용 API 금지 | 모든 모델을 로컬에서 실행한다 |
| 저작권 | 라이선스가 명시된 모델만 쓴다 (8절) |
| 재현성 | uv 환경 파일, 판정 결과 캐시, 처음부터 다시 실행하는 경로를 함께 낸다 |
| 데이터 보안 | 원자료와 가공 데이터를 공개 저장소에 올리지 않는다(`.gitignore`). 대회 후 폐기한다 |
| AI 활용 기록 | 작업하면서 주요 판단, 버린 대안, 실패 사례를 `docs/작업기록.md`에 쌓아 두고, 제출 때 여섯 항목으로 정리한다 |
