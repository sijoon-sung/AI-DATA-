## 1. 왜 이 문제가 신뢰성 연구의 좋은 시험대인가

결과물이 "항목별 서술형 + 근거 원문"이다. 즉 이 문제는 그 자체로 근거 기반 생성(RAG) 과제다. 게다가 대회 규정이 곧 신뢰성 요구사항이다.

| 대회 규정 | 대응하는 신뢰성 문제 |
|---|---|
| 판단 근거가 된 회의록명, 회의일자, 원문 구간을 제시 | 출처 귀속(attribution): 모든 주장에 실제로 그 주장을 뒷받침하는 원문이 붙어야 한다 |
| 의회 사이의 인과관계를 단정하지 않음 | 근거 수준에 맞는 표현: 생성문의 인과·확신 표현이 근거보다 강하면 안 된다 |
| 데이터 범위 안의 최초 관측 시점 | 시간 인지 검색: 가장 비슷한 문단이 아니라 가장 이른 문단을 찾아야 한다 |
| 기간 밖 정보 금지, 상용 API 금지 | 매개변수 지식 누출 통제, 로컬 오픈 모델 |
| 2024년 국회도서관 문제(회의록 챗봇)는 환각 여부를 중점 평가 | 환각률을 재고 줄이는 장치 |

회의록 RAG 챗봇은 이미 흔하다. 2024년 KISTI 대회에도 수상작이 있다. 그래서 차별점은 챗봇을 만드는 데 있지 않다. **흔한 RAG가 이 문제에서 어떻게 틀리는지 보이고, 그것을 고치는 방법을 측정으로 증명하는 데 있다.**

## 2. 연구 질문

**RQ1. 시간 인지 검색.** 유사도 상위 k 검색은 "최초 관측"과 "전파 경로" 질문에서 얼마나 틀리는가? 고재현율 검색과 검증은 이를 얼마나 고치는가?
- 문제의식: 일반 RAG는 가장 비슷한 문단을 가져오지, 가장 이른 문단을 가져오지 않는다. "최초"는 정밀도가 아니라 재현율의 문제다.
- 비교: (a) 밀집 검색 상위 k, (b) BM25 상위 k, (c) 하이브리드 검색 → 재순위 → 시간순 전수 확인.
- 지표: 최초 관측 일치율과 날짜 오차(사람이 추적한 이슈 20~30개 기준), 의회별 관측 재현율.

**RQ2. 구조화 근거 생성.** 문단을 그대로 LLM에 넣는 방식과, 사건표·연결·근거 수준으로 구조화한 근거 묶음을 넣는 방식 중 어느 쪽이 더 정확하고 근거에 충실한 서술을 만드는가?
- 비교: (a) 템플릿, (b) 일반 RAG(문단 → LLM), (c) 구조화 근거 묶음 → LLM, (d) (c) + 검증 후 재생성.
- 지표: 원자 주장 지지율, 인용 정밀도와 재현율, 날짜·순서 오류율, 읽기 좋은 정도(사람 평가 표본).

**RQ3. 주장 단위 검증.** 생성문을 원자 주장으로 나누고 세 단계로 검증하면 환각을 얼마나 걸러 내는가? 세 단계는 인용 문자열 일치, 함의 판정(NLI), 사건표 대조다. 자동 검증은 사람 판정과 얼마나 일치하는가?
- 지표: 사람 판정 기준의 검증기 정밀도와 재현율, 검증 뒤 남는 환각률.

**RQ4. 인과 과장 통제.** 생성문의 인과·확신 표현이 근거 수준을 넘는 비율(인과 과장률)은 얼마인가? 근거 수준을 조건으로 준 생성과, 과장을 찾아 다시 생성하는 방법은 이 비율을 얼마나 줄이는가?
- 근거 수준별로 허용 표현을 정한다. 예를 들어 명시적 참조는 "○○ 사례를 언급하며", 시간 선후는 "이후 관측됨"이다. "영향을 받아", "따라 도입" 같은 표현은 근거와 관계없이 금지한다.
- 과장 검출은 표현 사전과 분류기로 한다. 과학 문헌의 인과 표현을 분류한 연구(Yu 외 2019, 2020)의 틀을 회의록 서술에 옮긴다.
- 지표: 인과 과장률, 사람 판정과의 일치도.
- 이 문제에 가장 특화된 기여다. "인과 단정 금지"라는 규정을 측정할 수 있는 지표로 바꾼다.

**RQ5 (부수). 선택적 기권.** 근거가 모자랄 때 "확인 불가"라고 답하는 기준이 위험-적용범위 곡선에서 얼마나 좋은가?

## 3. 시스템

```
이슈 (L3 이슈 목록)
   │
[검색]  bge-m3 밀집+희소 → bge-reranker-v2-m3 → 시간순 전수 확인        ← RQ1
   │
[사건과 연결]  최초 관측, 관측 구간, 근거 수준, 이슈 유형 (L2 분류기, L4)
   │
[예측]  위험률 모형 + 요인별 근거 (L5)
   │
[구조화 근거 묶음]  JSON: 사건표, 연결과 근거 수준, 예측 요인, 원문 위치
   │
[생성]  Qwen2.5-7B-Instruct 4비트, 근거 수준을 조건으로 줌             ← RQ2, RQ4
   │
[검증]  인용 일치 → NLI 함의 → 사건표 대조 → 인과 과장 검출             ← RQ3, RQ4
   │      실패하면 다시 생성하거나 기권                                  ← RQ5
   │
결과표, 데모
```

L0~L5는 `04_아키텍처.md`와 `06_아이디어_검토.md`의 설계를 그대로 쓴다. 이 문서는 검색(L3)과 서술·검증(L6)을 연구의 중심으로 끌어올린 것이다.

## 9. 직접 관련된 선행연구

서지 정보는 기억에 의존해 적었다. 기술보고서에 인용하기 전에 원문으로 다시 확인한다.

- Gao 외 (EMNLP 2023), ALCE: 인용을 붙여 생성하는 LLM의 평가. 인용 정밀도와 재현율을 NLI로 잰다. RQ2, RQ3의 지표.
- Min 외 (EMNLP 2023), FActScore: 생성문을 원자 사실로 나눠 지지 여부를 잰다. RQ2, RQ3의 단위.
- Asai 외 (ICLR 2024), Self-RAG. Yan 외 (2024), Corrective RAG: 검색과 생성의 자기 점검. RQ3 설계의 비교 대상.
- Yu, Li & Wang (EMNLP 2019): 과학 문헌의 인과 표현 분류. Yu 외 (COLING 2020): 보도자료의 상관→인과 과장 측정. RQ4의 직접 선례.
- Zhou, Jurafsky & Hashimoto (EMNLP 2023): 언어모델의 불확실성·과신 표현. RQ4.
- Kamath, Jia & Liang (ACL 2020): 선택적 질의응답. RQ5.
